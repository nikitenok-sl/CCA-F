Утро экзамена

Шпаргалка читается за 10–15 минут, потом 20 вопросов на вкладке «Тренировка». Всё собрано из официального гайда и трудных тем остальных наборов.

Формат
60 вопросов, 120 минут, 4 сценария из 6. В каждом вопросе сказано, сколько ответов выбрать.
Темп
2 минуты на вопрос. Трудный отметьте флажком и идите дальше. Флажки проверьте в конце.
Порог
720 из 1000 по нелинейной шкале. В тренажёре ориентир 72% верных, но цельтесь в 80%, чтобы был запас.

Как выбирать ответ

  1. Деньги, безопасность, compliance — только детерминированно. Hook или программная проверка, а не инструкция в промпте.
  2. Пропорциональный первый шаг. Сначала описания инструментов, критерии и примеры. Классификатор, роутер, новая модель — почти всегда лишнее.
  3. Ищи корень выше по течению. Сабагенты отработали, а покрытия нет → декомпозиция координатора.
  4. «Больше» почти всегда ловушка: модель побольше, окно побольше, ещё ретраи, выше max_tokens, ещё прогоны с голосованием.
  5. Самооценка уверенности и тональность — не сигнал. Только явные критерии или калибровка на размеченных данных.
  6. Сабагент ничего не помнит и не наследует. Всё нужное передают явно в промпте.
  7. Ошибки структурированные, частичный результат лучше никакого. Не глушить ошибку и не ронять весь workflow.
  8. Правильный scope. Команде — проект (.claude/, .mcp.json, git). Себе — ~/.claude. Файлы одного типа по всему репо — .claude/rules/ с glob в paths.
  9. Несуществующие флаги и ключи — сразу мимо. CLAUDE_HEADLESS, --batch, .claude/config.json, shared_memory, confirm-destructive.

Частые ловушки

Темы, на которых ошибаются чаще всего.

Выбор двух ответов

  • Обычно в условии две проблемы: каждый верный вариант закрывает одну полностью.
  • Вариант, который чинит половину одной проблемы, — ловушка.
  • Оценивайте каждый вариант отдельно: «решает ли он одну из проблем сам по себе?»

Извлечение данных (сценарий 6)

  • Данных в документе нет → поле nullable, плюс в description «return null, do not estimate». Retry бесполезен.
  • Данные есть, но формат или структура не те → retry с документом, неудачным выводом и конкретной ошибкой.
  • Строгая схема гарантирует JSON, наличие полей и типы. Она не гарантирует правильные значения.

Форма схемы

  • Похожие поля путаются → в description писать, что поле IS и что IS NOT.
  • Повторяющиеся позиции → массив объектов, а не item_1…item_5.
  • Несколько значений (авторы) → массив. Своя категория → enum + "other" + detail. Извлечённое значение → строка.
  • Противоречие внутри документа → оба значения + conflict_detected.

Контекст: какой инструмент

  • Вывод навыка большой или исследовательский → context: fork.
  • Поиск по коду в середине задачи → Explore-сабагент.
  • Находки нужны на много вопросов вперёд → scratchpad-файл.
  • Контекст забит, а находки уже записаны → /compact.
  • Сбой процесса → manifest со состоянием агентов. Переход между фазами → сводка находок в промпт следующих сабагентов.

Длинный вход и история

  • Вход не влезает → upstream-агент отдаёт структуру, а не рассуждения. Ответы инструментов обрезаются до нужных полей.
  • Влезает, но середина теряется → сводка ключевых находок в начало и заголовки разделов.
  • Короткий диалог → полная история. Длинный → сводка + блок фактов вне сводки. Несколько заказов → структурированная запись на каждый.

tool_choice

  • "auto": агент иногда отвечает текстом (чат, уточняющий вопрос).
  • "any": вызов обязателен, а нужный инструмент зависит от входа.
  • forced {"type":"tool","name":…}: нужен именно этот инструмент, например первым шагом или при заранее известном типе документа.

Ревью

  • Много файлов → пофайловые проходы + отдельный интеграционный проход. Только пофайловые не видят межфайловых багов.
  • Ревьюер не должен видеть рассуждения генератора: только diff, требования и спецификацию.
  • Калиброванная уверенность распределяет внимание людей. Шум категорий, самопроверку и дубли она не лечит.
  • Повторный прогон: «новые или всё ещё не исправленные», а не «только новые».

Координатор

  • Вся связь идёт через координатора: прямые каналы и общие файлы ломают наблюдаемость и обработку ошибок.
  • Цикл доработки останавливается по проверяемому критерию, лимит раундов — только страховка.
  • Повторное поручение = пробел + прошлые запросы + найденные источники.
  • Субагенту дают цель и критерии качества, а не пошаговый рецепт.

Эскалация

  • Клиент явно просит человека → передать сразу, без расследования и встречных предложений.
  • Раздражён, но не просит → признать, предложить решение. Эскалировать, если повторит просьбу.
  • Политика молчит → эскалация. Несколько совпадений → спросить идентификатор.
  • При передаче: ID, первопричина, сумма, рекомендуемое действие.

Факты по доменам

D1 · Агенты · 27%

  • stop_reason: "tool_use" → выполнить и продолжить, "end_turn" → готово. "max_tokens" — обрезка, не готово.
  • Результат инструмента обязательно добавляют в историю.
  • Сабагенты: Task tool, "Task" в allowedTools, параллельно = несколько Task в одном ответе.
  • PreToolUse блокирует до вызова (refund больше $500). PostToolUse правит результат (форматы дат, PII).
  • --resume, если контекст актуален, плюс назвать изменённые файлы. Если много устарело → новая сессия со сводкой. fork_session → два подхода от общей базы.

D2 · Инструменты и MCP · 18%

  • Описание = главный механизм выбора: входы, что возвращает каждый путь, граничные случаи, отличие от соседа.
  • Инструмент с побочным эффектом разделяют на чтение и запись. Общий инструмент делят на целевые.
  • isError, errorCategory (transient, validation, permission, business), isRetryable. Пустой результат — не ошибка.
  • 4–5 инструментов на роль. Частую чужую задачу закрывает узкий инструмент (verify_fact).
  • .mcp.json + ${TOKEN} — для команды, ~/.claude.json — личное. Resources — каталоги без разведки. Grep ищет по содержимому, Glob по путям.

D3 · Claude Code · 20%

  • Поведение отличается у людей или сессий → сначала /memory.
  • CLAUDE.md подпапки грузится при работе с её файлами. .claude/rules/ с paths — при Read, Write, Edit подходящего файла. Импорт: @path.
  • SKILL.md: argument-hint (нет параметров), allowed-tools (опасные действия), context: fork (вывод и исследование).
  • Skill — по требованию, CLAUDE.md — всегда. Личный вариант навыка — в ~/.claude/skills/ под другим именем.
  • Plan mode для архитектуры и многих файлов, direct для ясной правки. CI: -p, --output-format json + --json-schema → structured_output.

D4 · Промпты · 20%

  • «Будь консервативен» не работает. Работает «флаговать только если…» и явный skip-список.
  • Неполное ≠ неточное. Устаревшее по стилю ≠ неверное. FIXME про исправленный баг — флаговать.
  • Шумную категорию временно выключить, severity задать примерами кода.
  • Few-shot: 2–4 примера с рассуждением, один пример с «no finding» или null.
  • Batch: −50%, до 24 ч, без SLA, без tool loop, custom_id. Окно отправки = SLA − 24 ч.

D5 · Контекст и надёжность · 15%

  • Блок case facts (суммы, даты, номера) держат вне сводки.
  • Признаки деградации: «typical patterns», противоречия, переспрашивает уже известное.
  • Сабагент сам повторяет transient-ошибку, наверх передаёт только нерешённое, с частичными результатами.
  • 97% в среднем могут скрывать провал сегмента. Проверять по типам документов и полям, делать стратифицированную выборку уверенных извлечений.
  • Сохранять связь claim → source и даты. Конфликт — оба значения с атрибуцией. Разные годы — это динамика, не конфликт.
