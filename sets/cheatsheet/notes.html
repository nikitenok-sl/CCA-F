Что в шпаргалке не так

cheatsheet.md сверен с официальным Exam Guide v1.0, документацией Claude Code, Message Batches API и спецификацией MCP. Эти утверждения в вопросы не попали.

  • Экзамен стоит $99, прокторинг ProctorFree, результат до 7 рабочих дней$125, Pearson VUE (онлайн или центр), pass/fail и балл в отчёте
  • В банке 8 сценариев, включая Conversational AI и Agentic ToolsВ гайде 6 сценариев, на экзамене 4 случайных из них
  • Path-scoped rules срабатывают только при чтении, при создании файла не грузятсяПравило грузится, когда Claude вызывает Read, Write или Edit для подходящего файла
  • В батче максимум 10 000 запросовДо 100 000 запросов или 256 MB. Размеры на экзамене не проверяют
  • MCP prompts контролирует приложениеСпецификация MCP: tools контролирует модель, resources выбирает приложение, prompts выбирает пользователь (например, slash-команды)
  • Отказ по бизнес-правилу всегда возвращается с isError: falseВ спецификации MCP business logic errors возвращаются с isError: true, гайд выделяет их в отдельную категорию с retriable: false. Не ошибка только пустой результат успешного запроса
  • Инструменты никогда не объединяютГайд считает объединение допустимым архитектурным решением. Просто это не самый дешёвый первый шаг
  • Импорт пишется как @import docs/file.mdСинтаксис @docs/file.md
  • Правило в промпте соблюдается в 95–98% случаевЦифра из фольклора. Гайд говорит только, что у промпта ненулевой процент отказа

9 правил выбора ответа

Применять по порядку: решает первое подходящее правило.

  1. Код гарантирует, промпт предлагает. Деньги, право, compliance решаются hook'ом, а не промптом.
  2. Цикл останавливает только stop_reason. "end_turn" значит готово, "tool_use" значит выполнить и продолжить. Ни текст, ни число итераций, ни длина ответа сигналом не являются.
  3. Эскалация по явным критериям, не по эмоциям. Явная просьба о человеке, пробел в политике, нет прогресса.
  4. Ограничивай, а не добавляй. Меньше инструментов, точнее схема, примеры прицельнее.
  5. Сначала описания, потом классификаторы. Сначала community, потом свой сервер.
  6. Сабагент не наследует контекст. Всё нужное передаётся явно.
  7. Ищи корневую причину. Пропущены темы, значит виновата декомпозиция координатора. Выдуманное значение, значит поле надо сделать nullable. Новичок не видит правил, значит они лежат в user-level конфиге.
  8. Частичный результат лучше никакого. Продолжай с тем, что есть, и помечай пробелы.
  9. Разные годы не означают конфликт. 2023 и 2024 — это динамика, а не противоречие.

Чек-лист перед ответом

  1. Высокие ставки? Нужно программное решение.
  2. Вопрос про завершение цикла? Только stop_reason.
  3. Вопрос про эскалацию? Только явная просьба или пробел в политике.
  4. Вариант добавляет ещё что-то? Скорее всего неверный.
  5. Вариант лечит симптом? Ищи корневую причину.
  6. Вариант предполагает, что сабагент знает контекст? Неверно.
  7. Гарантию обещает промпт? Неверно.

Если подходят два варианта, выбирай детерминированный, а не вероятностный.

Ключевые таблицы шпаргалки

Сессии

  • Разбирались 2 часа назад, коммитов не было → resume.
  • Вчера, с тех пор смержены 3 PR → новая сессия с резюме.
  • Два расходящихся подхода от общего анализа → fork_session. Если подходы последовательные, просто продолжай сессию.
  • Агент говорит «typical patterns» → вынести находки, затем новая сессия или /compact.
  • Упал посреди задачи, есть manifest.json → продолжить по манифесту.
  • День 2, вчера Auth, сегодня Payments → передать ключевые выводы по Auth, а не всю историю.

Hook или промпт

  • Лог каждого вызова для аудита → hook: в журнале не должно быть пропусков.
  • Проверка личности перед чтением чувствительных данных → hook.
  • Маскировка PII в ответах инструментов → hook.
  • Проверка склада перед обещанием доставки → hook.
  • Сначала поздороваться, ссылаться на источники → промпт: это предпочтение, а не безопасность.
  • Тест: если правило нарушится в 2% случаев, будет ли это серьёзно? Да → hook.

Ответы MCP-инструментов

  • Ничего не найдено при успешном запросе → не ошибка. Не повторять.
  • Несколько совпадений → успешный ответ, нужно уточнение у клиента.
  • Timeout, 503, 429 → isError, transient, retryable, желательно retry_after_seconds.
  • Неверный ввод → validation, исправить ввод. Нет доступа → permission.
  • Сабагент сделал часть работы → status partial: что готово, что нет и можно ли повторить.

Схемы извлечения

  • Поле может отсутствовать → ["string","null"], и в description: «return null, do not estimate».
  • Похожие поля → в description писать, чем поле является и чем НЕ является (due_date и invoice_date).
  • Enum для своих категорий (с "other"). Извлекаемые значения, например vendor_name, оставлять свободной строкой.
  • item_1_name, item_2_name → модель выдумает третий. Нужен массив line_items.
  • Авторов может быть несколько → authors массивом.
  • tool_use гарантирует валидный JSON и типы, но не верность значений.

Контекст

  • Признаки деградации: общие слова вместо конкретики, противоречит сказанному раньше, переспрашивает уже известное.
  • Блок фактов (суммы, ID, даты) никогда не сжимается и добавляется к любой стратегии истории.
  • Ключевые находки ставь в начало контекста.
  • Финансы показывай таблицей, новости прозой, технику списком, динамику по датам.

Batch API

  • −50%, до 24 часов, без SLA, без tool calling внутри запроса.
  • Окно отправки = SLA − 24 ч. Если ≤ 0, нужен синхронный API.
  • Результаты сопоставляются по custom_id, порядок не гарантирован.
  • Повторно отправлять только упавшие custom_id.
